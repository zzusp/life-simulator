# 端到端自测指南

## 概述

本文档提供完整的端到端测试路径，覆盖所有关键用户流程和交互场景，确保 UI/UX 重设计的完整性与一致性。

## 测试环境准备

### 前置条件
1. 数据库已初始化并包含测试数据
2. 开发服务器已启动 (`npm run dev`)
3. 浏览器已打开开发者工具（用于观察网络请求和控制台）

### 测试浏览器
- Chrome/Edge (推荐)
- Firefox
- Safari (macOS/iOS)
- 移动端浏览器

---

## 测试路径 1: 完整游戏流程（首次用户）

### 目标
模拟首次用户完整体验游戏并分享结果的流程。

### 步骤

#### 1.1 首页（`/`）
- [x] 页面加载速度 < 2秒
- [x] 标题 "人生模拟器" 清晰可见
- [x] 副标题描述完整显示
- [x] "开始游戏" 按钮高亮显示（视觉主 CTA）
- [x] **键盘测试**: Tab 键聚焦到 "开始游戏" 按钮，焦点环清晰可见
- [x] **键盘测试**: 按 Enter 或 Space 键，页面跳转到游戏主页

**期望**: 平滑过渡动画（200-250ms），无闪烁

#### 1.2 游戏主页（`/game`）
- [x] 页面加载后显示 "玩法说明" 三栏布局
- [x] 人生类型列表正确加载（至少 3 种）
- [x] 每个类型卡片包含：标题、描述、初始身份、主要目标
- [x] **键盘测试**: Tab 键依次聚焦到类型卡片，焦点环清晰
- [x] **键盘测试**: 在卡片上按 Enter 或 Space，选中卡片并高亮
- [x] 选中卡片后边框变为主色调（蓝色），背景轻微着色
- [x] "选择此人生" 按钮变为激活状态
- [x] 点击 "选择此人生" 后显示加载状态

**期望**: 卡片过渡动画流畅，加载状态清晰，无跳跃

#### 1.3 游戏场景（`/play/[sessionId]`）

##### 1.3.1 首个场景
- [x] 场景标题、编号、当前分数正确显示
- [x] 场景描述完整可读
- [x] 选择项（2-4 个）清晰展示
- [x] 每个选择包含：选择文本、辅助说明（可选）、分数影响
- [x] **键盘测试**: Tab 键聚焦到选择卡片，焦点环清晰
- [x] **键盘测试**: 在选择上按 Enter 或 Space，触发选择

##### 1.3.2 选择处理
- [x] 点击选择后，该选择卡片高亮（边框+背景色）
- [x] 其他选择卡片变为禁用态（半透明 + 不可点击）
- [x] 显示半透明遮罩 "AI正在生成下一个场景..."
- [x] 处理时间 < 5秒

**期望**: 禁用态过渡平滑，遮罩动画自然

##### 1.3.3 分数变化动画
- [x] 分数数字以动画形式更新（0.8-1.2秒）
- [x] 分数变化伴随颜色渐变（正面=绿色，负面=红色）
- [x] 分数标签同步更新（卓越/优秀/良好等）

##### 1.3.4 成就解锁提示
- [x] 成就提示以 Toast 形式从顶部/右侧滑入
- [x] 显示成就图标、名称、描述
- [x] 多个成就严格串行显示（并发=1，间隔≥300ms）
- [x] 单条提示显示 3-5 秒后自动消失
- [x] **减少动效测试**: 在系统偏好设置中启用 "减少动效"，Toast 应立即显示/消失

**期望**: Toast 动画流畅，不阻塞主界面操作

##### 1.3.5 后续场景
- [x] 重复步骤 1.3.1 - 1.3.4，进行 3-5 次选择
- [x] 每次场景过渡平滑，无内容跳跃
- [x] 分数累积正确

##### 1.3.6 游戏结束条件
- [x] 当分数达到 100 或 0 时，自动跳转到结果页
- [x] 或达到预设场景数（如 10 个）后结束

#### 1.4 游戏结果（`/play/[sessionId]` 结果区域）
- [x] 结果标题根据最终分数显示（成功/失败/一般）
- [x] 结果描述清晰说明结局
- [x] 统计卡片三栏布局：最终分数、选择次数、游戏时长
- [x] 分数以色阶显示（绿/黄/橙/红）
- [x] 成就列表（如有）正确展示
- [x] 选择历史逐条展示，包含分数变化
- [x] **操作按钮**:
  - [x] "重新开始" 按钮跳转到 `/game`
  - [x] "查看历史" 按钮跳转到 `/history`
  - [x] "分享结果" 按钮触发分享

#### 1.5 分享结果
- [x] 点击 "分享结果" 后显示加载状态
- [x] 成功后显示分享链接或复制到剪贴板提示
- [x] **错误处理**: 模拟网络错误，应显示内嵌错误区块（图标+标题+说明+重试按钮）

**期望**: 分享操作流畅，错误提示清晰

## 测试路径 4: 可达性测试

### 目标
验证键盘导航、焦点管理、屏幕阅读器兼容性。

### 步骤

#### 4.1 全站键盘导航
- [x] **首页**: Tab 键聚焦到 "开始游戏" 按钮
- [x] **游戏主页**: Tab 键依次聚焦到类型卡片和按钮
- [x] **游戏场景**: Tab 键聚焦到选择卡片
- [x] **结果页**: Tab 键聚焦到操作按钮
- [x] **历史页**: Tab 键聚焦到历史卡片

#### 4.2 焦点可见性
- [x] 所有交互元素在获得焦点时显示清晰的焦点环
- [x] 焦点环颜色为主色调（蓝色），宽度 2px，偏移 2px
- [x] 焦点环不与元素边框冲突

#### 4.3 减少动效支持
- [x] 在系统偏好设置中启用 "减少动效" (Windows: 设置 > 轻松使用 > 显示 > 显示动画)
- [x] 刷新页面，所有动画时长应缩短至 0.01ms
- [x] 页面过渡、Toast、加载动画立即完成

#### 4.4 屏幕阅读器测试（可选）
- [ ] 使用 NVDA (Windows) 或 VoiceOver (macOS) 测试
- [ ] 所有交互元素具有正确的 `aria-label`
- [ ] 焦点顺序逻辑合理
